# 全5回の進め方

## 開始前：まず完成形を動かす

[Quickstart](../quickstart.ipynb)を上から順に実行します。
全5回で扱うコードが1本につながっていることと、最後に予測結果が出ることを確認します。
この段階でコードを全て理解する必要はありません。

## 1回あたりの学習量

Notebookだけで完結させず、外部資料と組み合わせます。1回あたり合計4時間30分〜6時間30分が目安です。

| 区分 | 時間 | 内容 |
|---|---:|---|
| 事前学習 | 100〜160分 | 指定された外部資料を読み、確認問題へ答える |
| 勉強会 | 120分 | Notebookを動かし、結果を比較する |
| 復習 | 50〜105分 | 追加演習を行い、結果と疑問を記録する |

外部資料の指定範囲と確認問題は[外部資料の学習ガイド](resources.md)にまとめています。

## 勉強会120分の進め方

| 時間 | 内容 |
|---:|---|
| 0〜10分 | 今日できるようになることを確認する |
| 10〜30分 | 外部資料の確認問題を話し合う |
| 30〜55分 | 講師と一緒にNotebookを動かす |
| 55〜95分 | 各自でコードを実行し、値を1つ変える |
| 95〜110分 | 結果の違いと理由を話す |
| 110〜120分 | 分かったことと次に試すことを書く |

止まった場合は、前のセルから順に実行し直します。5分で解決しない環境問題は講師が控え、
参加者は講師PCの結果を見ながら本題を続けます。

## 第1回：Pythonの基礎とpandas・NumPy

**到達点**：短いPythonコードを読み、表データから必要な行や集計結果を取り出せる。

- 変数、リスト、繰り返し、関数を使う
- NumPyの配列で計算する
- pandasでCSVを読み、確認・抽出・集計する
- 欠損値を確認する
- データ型、代表値、ばらつき、グラフの選び方を知る
- エラーの読み方とNotebookの実行順を確認する

最後に、抽出条件や集計する列を1つ変えて結果を比べます。

## 第2回：scikit-learnと機械学習

**到達点**：分類と回帰の違いを説明し、学習と予測の基本コードを実行できる。

- 特徴量と目的変数を分ける
- 学習用と検証用のデータを分ける
- 数値を予測する回帰を試す
- クラスを予測する分類を試す
- 単純な予測と比べる
- 問い、予測時点、目的変数、利用可能な列を決める
- 数値・カテゴリ・欠損をPipelineで前処理する
- 過学習、未学習、データリークを区別する

モデル名の暗記より、`fit`へ渡すものと`predict`から返るものを確認します。

## 第3回：高度な予測モデル

**到達点**：決定木、Random Forest、GBDTを同じ条件で比べられる。

- 1本の決定木を動かす
- 複数の木を使うRandom Forestを動かす
- GBDTが前の誤りを順に補う様子を見る
- 学習率や木の数を変える
- 任意でXGBoostを試す
- 線形モデルと木モデルの得意・不得意を比べる
- バギングとブースティングの違いを知る
- 学習性能と検証性能の差から過学習を判断する
- 学習時間、予測時間、説明しやすさも比較する

複雑なモデルが必ず良いとは限らないことを、検証結果で確かめます。

## 第4回：予測モデルを評価する

**到達点**：1つの点数だけで判断せず、用途に合う指標と検証方法を選べる。

- 分類の適合率、再現率、F1、混同行列を読む
- しきい値を変えて誤り方の変化を見る
- 回帰のMAE、RMSE、R²を読む
- 残差が大きいデータを確認する
- 交差検証で結果のばらつきを見る
- 層化、グループ、時系列に応じて分割方法を変える
- クラス不均衡とベースラインを確認する
- 評価指標を利用時の損失と結び付ける
- 誤分類と大きな残差を元の行まで戻って確認する

偽陽性と偽陰性のどちらを減らしたいかを、利用場面から考えます。

## 第5回：性能を向上させる

**到達点**：比較条件をそろえ、改善案を1つずつ試して記録できる。

- 役立ちそうな特徴量を作る
- `RandomizedSearchCV`で設定を探す
- 学習に使っていない予測でしきい値を決める
- 特徴量を並べ替えて重要度を調べる
- 変更前後を同じ指標で比べる
- 学習曲線からデータ追加とモデル変更の優先度を考える
- 特徴量作成と特徴量選択を区別する
- 設定探索の結果を最終性能と混同しない
- 乱数、環境、実験条件を残して再現できるようにする
- 仮説、変更、結果、判断、次の実験を表に残す
- 重要度を因果関係として解釈しない

一度だけ高い点数が出たことを改善とはしません。変更点、結果、次に試すことを残します。
