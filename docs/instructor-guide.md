# 講師用進行ガイド

## このガイドの役割

講義内容を読み上げる台本ではなく、5人の参加者がコードを動かし、結果について話す時間を守るための進行メモです。参加者の経験差は、全員が別の課題を行うのではなく、同じNotebookの`TRY`までを共有し、経験者だけ`CHANGE`や`CHALLENGE`を広げることで吸収します。

## 開講前の準備

1. Windows PCで[セットアップ手順](setup-windows.md)を最初から確認する
2. `uv sync`と環境チェックを行う
3. 全Notebookの実行チェックを行う
4. 参加者へGitHubのリポジトリURLとZIPの展開先を案内する
5. M365 Copilotへ入力してよい情報の社内ルールを確認する

```powershell
uv sync
uv run python scripts/check_environment.py
uv run python scripts/validate_materials.py --execute
```

## 毎回の準備

- 該当回の`lesson.ipynb`を上から最後まで実行する
- その回で変える値を1つ決め、講師自身の結果を控える
- `TRY`開始時点のNotebookを参加者が開けるか確認する
- 共有用に「面白かった結果」を書く場所を1つ用意する
- 自習していない参加者を前提に、前回の必須知識を1分で言い直す

## 90分の進行

| 時間 | 講師の動き | 参加者の動き |
|---:|---|---|
| 0～10分 | 前回の結果を2つ拾う | 気づきを一言共有 |
| 10～25分 | 今日の問いと図を示す | 予想を言葉にする |
| 25～45分 | 途中で止まりながら実演 | 出力を予想する |
| 45～75分 | `TRY`を巡回支援 | 全員がコードを動かす |
| 75～85分 | 5人の結果を並べる | 違いを説明する |
| 85～90分 | 1行まとめと次回予告 | 任意課題を選ぶ |

## つまずいたときの優先順位

1. Notebookのカーネルが`.venv\Scripts\python.exe`か
2. エラーが出たセルより前を順番に実行したか
3. 教材原本ではなく`workspace`へコピーしたか
4. エラー全文を読める状態か
5. 5分で直らなければ講師PCの画面で本題を継続できるか

環境トラブルを全員で待たず、本人と講師が後で直せるよう画面を残します。

## 各回の講師メモ

### 第1回：予測モデルを動かす

- ゴール：`fit`と`predict`を説明できなくても、入力と出力を指させる
- 見せ場：1試料の活性確率が表示されるセル
- よくある誤解：確率が高ければ真実になる、学習データが多ければ必ず正しい
- 経験者：`max_depth`だけを変え、検証結果を比較する

### 第2回：PythonとCopilot

- ゴール：分からないコードを小さく切り、型と中身を確認する
- 見せ場：エラー名とメッセージを省略せず表示する
- よくある誤解：Copilotのコードは実行できれば正しい
- 経験者：関数の入力チェックまたは型ヒントを追加する

### 第3回：pandas

- ゴール：`head`、`shape`、`dtypes`、欠損数を自力で確認する
- 見せ場：5人が異なるカテゴリで集計し、順位が変わる
- よくある誤解：行番号と`sample_id`は同じもの
- 経験者：複数条件、`groupby`、`agg`を組み合わせる

### 第4回：EDA

- ゴール：グラフから断定ではなく仮説を1つ作る
- 見せ場：温度180℃、反応時間72時間の行を見つける
- よくある誤解：外れ値は自動的に削除する
- 経験者：バッチまたは系列で色分けし、見え方を比べる

### 第5回：問題設定

- ゴール：「誰が・いつ・何を予測し・どう使うか」を1文にする
- 見せ場：`post_assay_signal`が高性能でも利用不可と判断する
- よくある誤解：目的変数と説明変数をモデルが自動で決める
- 経験者：現在の業務判断をDummyモデルとして定義する

### 第6回：検証とリーク

- ゴール：学習用・検証用・テスト用の役割を区別する
- 見せ場：リーク列でスコアが不自然に上がる
- よくある誤解：高い検証スコアは必ず良い知らせ
- 経験者：`scaffold_group`単位の分割をランダム分割と比べる

### 第7回：回帰

- ゴール：Dummyより良いか、誤差の単位は何かを説明する
- 見せ場：最も大きく外した8試料
- よくある誤解：R²だけでモデルの価値が決まる
- 経験者：残差を触媒や系列で分ける

### 第8回：分類

- ゴール：偽陽性と偽陰性を利用場面に結びつける
- 見せ場：閾値0.3、0.5、0.7でprecisionとrecallが動く
- よくある誤解：閾値0.5は常に最適
- 経験者：目的に合わせた閾値を提案し、理由を書く

### 第9回：Pipeline

- ゴール：前処理もモデルの一部として一緒に学習する理由を知る
- 見せ場：未知の溶媒名でもエラーにならない
- よくある誤解：欠損補完を全データで先に行ってよい
- 経験者：変換後の特徴量名を確認する

### 第10回：モデル比較

- ゴール：同じ分割・指標で比べ、用途別に候補を選ぶ
- 見せ場：5人が1モデルずつ担当して比較表を完成させる
- よくある誤解：最も複雑なモデルが常に勝つ
- 経験者：実行時間と学習・検証差も記録する

### 第11回：特徴量

- ゴール：化学的仮説を、予測時点で計算可能な式へ変える
- 見せ場：特徴量追加前後を同じ分割で比較する
- よくある誤解：特徴量は多いほどよい
- 経験者：RDKitを有効にし、1記述子を再計算する

### 第12回：改善サイクル

- ゴール：変更点を1つに限定し、平均とばらつきを記録する
- 見せ場：`max_depth`だけの実験ログ
- よくある誤解：一度だけ高いスコアが出れば改善
- 経験者：重要度から反証可能な次の仮説を作る

### 第13回：最初の提出

- ゴール：問題・指標・train/test・提出形式を確認してCSVを作る
- 見せ場：3つの`assert`を通して提出形式を検査する
- よくある誤解：提出先が正しい形式へ直してくれる
- 経験者：ベースラインを壊さず別モデルを試す

### 第14回：改善会

- ゴール：5人の変更を実験ログへ残し、良い案だけ統合する
- 見せ場：ローカルF1と模擬Leaderboard F1が一致しない場合
- よくある誤解：Leaderboardだけを見て変更を選ぶ
- 経験者：誤分類を系列別に調べる

### 第15回：Show & Tell

- ゴール：成果の完成度ではなく、次に試す小さな問いを持ち帰る
- 見せ場：失敗から得た学びも同じ重さで共有する
- よくある誤解：自社データをその場でCopilotへ貼ってよい
- 経験者：分割単位、ベースライン、利用者まで1枚シートに書く

## 研修後に残すもの

- 参加者が変更したNotebook
- 5人分の実験ログ
- 良かったCopilotプロンプト
- 自社テーマ1枚シート（機密情報を除く）
- 次回実施時に変えたい点を3つ以内
