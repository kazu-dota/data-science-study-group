# Python環境とGitの基礎（任意）

この勉強会の必須操作は、[Windows環境の準備](setup-windows.md)に書かれた`uv sync`だけです。
このページは、「機械学習だけでなく、自分のPCの中でPythonがどう動いているかも理解したい」
「Gitも触ってみたい」という人向けの、任意の追加資料です。読まなくても各回には参加できます。

## そもそも「環境」とは何か

Pythonを使うプロジェクトでは、プロジェクトごとに「使うPythonのバージョン」や「入れておく
ライブラリの種類・バージョン」が違います。あるプロジェクトはpandas 2.0を使い、別のプロジェクトは
pandas 1.5でないと動かない、ということも起こります。

そこで、プロジェクトごとにPythonとライブラリ一式を**別の場所に分けて用意**し、混ざらないようにします。
この「分けて用意した場所」のことを**仮想環境**と呼びます。この勉強会でいう`.venv`フォルダが、
この教材専用の仮想環境です。

## この勉強会がuvを使う理由

`uv`は、仮想環境の作成と、必要なライブラリのインストールを両方行うツールです。この勉強会で採用した理由は次のとおりです。

- `pyproject.toml`と`uv.lock`に、使うライブラリとバージョンが正確に記録されており、`uv sync`一発で
  誰のPCでも同じ環境を再現できる
- インストールが速い
- Windows + VS Codeでの構築手順がシンプルで、Gitのインストールも不要にできる

## Condaとの違い

データサイエンス分野では、`uv`の他に**Conda**（Anaconda／Miniconda）もよく使われています。
どちらも「環境を分けて再現する」ためのツールですが、得意分野が少し違います。

| | uv | Conda |
|---|---|---|
| 主な対象 | Pythonのライブラリ | Python本体を含む、非Pythonのソフトウェアも扱える |
| 得意な場面 | 純粋なPythonプロジェクトを、速く・軽く構築する | RDKitのように、C/Fortranなどで書かれた部分を含む科学技術系ライブラリを扱う |
| この勉強会での位置づけ | 標準環境として採用 | 未使用（第4回パート2のRDKitは、`uv sync --extra chemistry`で導入できる） |

どちらが優れているというより、**プロジェクトの性質に合わせて選ぶもの**です。化学・創薬分野の
研究では、RDKitや量子化学計算ソフトのように、Pythonだけでは完結しないライブラリを使う場面も多く、
そうした現場ではCondaも広く使われています。この勉強会では構築のしやすさを優先して`uv`を選びましたが、
将来Condaを使う環境に出会っても、「仮想環境を分けて再現する」という考え方自体は同じです。

## 自分のPCにある複数のPython環境を確認する

VS Codeのターミナルで次を実行すると、今使われているPythonの場所が分かります。

```powershell
uv run python -c "import sys; print(sys.executable)"
```

`...\.venv\Scripts\python.exe`のように、勉強会フォルダの中の`.venv`を指していれば正しい環境です。
Notebookの右上にある「カーネルの選択」も、同じ`.venv\Scripts\python.exe`を選んでいるか確認できます。

## Gitを知りたい人へ

Gitは、ファイルの変更履歴を記録し、後から見返したり元に戻したりできるようにする**バージョン管理システム**です。
この勉強会自体もGitで管理されており、GitHub上で公開されています。ただし参加にGitの知識は不要で、
ZIPダウンロードだけで完結するようにしてあります。

興味がある人のために、最低限の用語を紹介します。

- **リポジトリ（repository）**：ファイルとその変更履歴をまとめて保存する場所。このプロジェクト全体が1つのリポジトリです。
- **コミット（commit）**：「ここまでの変更」に名前（メッセージ）を付けて記録する操作。写真のスナップショットのように、その時点の状態を保存します。
- **クローン（clone）**：リポジトリを丸ごと自分のPCへコピーすること。ZIPダウンロードに近いですが、履歴も含めてコピーされ、後から`pull`で更新できます。
- **プル（pull）**：リポジトリの最新の変更を、自分のPCへ取り込むこと。
- **プッシュ（push）**：自分のPCで行った変更を、リポジトリ側へ反映すること。
- **ブランチ（branch）**：同じリポジトリの中で、複数の変更を並行して進めるための分岐。

実際に`clone`と`pull`を試す手順は、[Windows環境の準備「Gitを試したい人向け（任意）」](setup-windows.md#gitを試したい人向け任意)にあります。
まずは上の用語だけ頭に入れて、実際に手を動かすとイメージがつかみやすくなります。より体系的に学びたい場合は、
Git公式のドキュメント（[git-scm.com/book/ja/v2](https://git-scm.com/book/ja/v2)）が日本語で読めて詳しいです。
