# 生成AIっぽい日本語の検出と是正

## このスキルの目的と大原則

日本語の文章を、**自然で・明快で・書き手の視点が定まった**ものにする。目的は表面的な言い回しだけを探すことではなく、
読み手にとって分かりやすくすること。

**過剰矯正をしない（最重要）。** 以下はすべて「悪」ではない。文脈次第で適切なことも多い。

- 箇条書き・太字・見出しそのものは悪ではない。教材や手順書ではむしろ有効。**多用・機械的な乱用**だけが問題。
- 丁寧語・敬体も悪ではない。**過剰な丁寧さ・空疎な結び**が問題。
- 1つ2つ当てはまるだけでは指摘しない。**複数の兆候が重なって読みにくい／中身が薄い**箇所だけを挙げる。

指摘は「これはAI臭いから直せ」ではなく、「**読み手にこう伝わりにくい → こう直すと明快**」という形にする。

## チェックリスト（兆候カテゴリ）

### A. 中身の薄い定型表現・断定回避

根拠を伴わずに「重要」「大切」で締める、断定を避けてぼかす言い回し。

- ✗ 「〜が重要です」「〜が大切です」で終わり、なぜ重要かが無い
- ✗ 「〜と言えるでしょう」「〜ではないでしょうか」「〜が求められています」「〜が望ましいでしょう」
- ✗ 「〜において」「〜に関して」「〜という点で」の空回り
- ✓ 具体を伴わせる：「重要です」→「これを怠ると検証スコアが実力より高く見え、判断を誤ります」

### B. 抽象的で大きい物言い・自信過剰な一般論

中身の薄い一般論を、断定口調で堂々と述べる。

- ✗ 「データの本質を捉え」「価値を最大化し」「新たな可能性を切り拓く」
- ✓ その回・そのコードで実際に起きることに落とす

### C. 装飾・強調の機械的な多用

- ✗ 1段落に太字が何度も出る／全項目が「**語**：説明」の同型で並ぶ
- ✗ 中黒（——）や絵文字での飾り、意味の薄い箇条書き化
- ✓ 強調は本当に効かせたい1〜2語に絞る。散文で足りる所は散文で書く

### D. 冗長な前置き・画一的な構成

- ✗ 「まず結論を述べ、次に理由を列挙し、最後にまとめる」型が全セルで判で押したように反復
- ✗ 「〜について見ていきましょう」「それでは〜していきます」等の内容の無い導入
- ✓ いきなり本題に入る。同じ回で導入の型を毎回変える

### E. 過剰な反復・くどさ

- ✗ 同じ語・同じ言い回し（「〜という考え方」「〜が肝心」など）が近接して何度も出る
- ✓ 一度言えば十分な念押しは削る

### F. 翻訳調・不自然なカタカナ

- ✗ 英語直訳的な構文、無理なカタカナ語（意味の通る和語があるのに）
- ✗ 主語の過剰な明示（「私たちは〜します」の乱発）

### G. 視点のあいまい・主観/客観の取り違え（特に注意）

- ✗ **誰の視点かが不明**：「〜と感じられます」「〜と考えられています」で、書き手なのか一般論なのか読者なのか曖昧
- ✗ **主観を客観に偽装**：本来は書き手の判断・おすすめなのに「〜とされている」「一般に〜が良いとされる」と第三者化して逃げる
- ✗ **客観を主観にすり替え**：事実・定義を「〜だと思います」と弱める
- ✓ 教材なら「（あなたが）〜してみましょう」「（このデータでは）〜になります」「筆者の推奨は〜」のように、**誰の言葉か**を一文の中で確定させる。事実は言い切り、意見は意見と分かる形にする

### H. 表記・文法の乱れ

- ✗ 敬体（です・ます）と常体（だ・である）の不用意な混在
- ✗ 助詞の不自然（「を」「が」「は」の誤選択）、同音異義語の変換ミス、係り受けの破綻
- ✗ 一文が長すぎて主語と述語が離れる

## レビュー手順

1. 対象文を読み、A〜Hのどれに当たるかで**兆候が重なって読みにくい箇所**を拾う。単発の軽微は原則スルー。
2. 各指摘は必ず **該当箇所（ファイル/セル・原文の引用）→ 何が問題か（読み手にどう伝わりにくいか）→ 書き換え例（before→after）** の3点で書く。
3. 深刻度を付ける：**高**＝意味が誤解される/事実と意見が混線、**中**＝読みにくい/くどい、**低**＝好みの範囲。
4. **過剰指摘の自己点検**：挙げた指摘を見返し、「これは直さなくても自然に読める」ものを落とす。指摘の数を増やすことを目的にしない。

## 出力形式（レビュー時）

- 総括（数文）：全体として自然か、どの兆候が目立つか。
- 深刻度別の指摘リスト（高→中→低）：各項目 before→after 付き。
- 良い点：自然で明快に書けている箇所も挙げ、基準の妥当性を示す。
- 最後に「これ以上は過剰矯正になる」というラインを一言添える。
