# 第5回：提出から運用・監視・再学習（MLOps）へ

この回は旧カリキュラムの3回分に、MLOps（運用）の視点を足した最終回です。次の構成です。

- **パート1：Kaggleに入って最初の提出を作る** — コンペの説明を、ローカルの分析手順へどう翻訳するか。
- **パート2：Kaggle改善会** — 限られた時間で、次に何を試すか。
- **パート3：Show & Tellと自社データへの橋渡し** — 自社データで始めるなら、最初の小さな一歩は何か。
- **パート4：MLOpsの考え方（運用・監視・再学習）** — モデルを「作って終わり」にせず、学習→提供→監視→再学習のループへつなぐ。

## 進め方

パート1→4の順に進めます。各パートの`DEEP DIVE`／`APPENDIX`は、余裕のある人や自習で。

- 実習は [lesson.ipynb](lesson.ipynb) を使います。
- Kaggleアカウントが使える人向けの任意実践として [titanic_optional.ipynb](titanic_optional.ipynb) があります（本編は模擬コンペで完結します）。

記号（`CORE`・`DEEP DIVE`など）の意味は [README「Notebookの目印」](../../README.md#notebookの目印) を参照します。
